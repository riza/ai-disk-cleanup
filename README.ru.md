# ai-disk-cleanup

**Найдите, чем забит диск, с помощью ИИ-агента — и не дайте ему удалить то, что вы не одобрили.**

[![X](https://img.shields.io/badge/X-%40rizasabuncu-000000?style=flat&logo=x&logoColor=white)](https://x.com/rizasabuncu) [![Buy Me a Coffee](https://img.shields.io/badge/Buy%20Me%20a%20Coffee-FFDD00?style=flat&logo=buymeacoffee&logoColor=black)](https://buymeacoffee.com/rizasabuncu)

[English](README.md) · [Türkçe](README.tr.md) · [简体中文](README.zh-CN.md) · [Español](README.es.md) · **Русский** · [Português (BR)](README.pt-BR.md) · [日本語](README.ja.md)

Промпт и два небольших инструмента. Агент (Claude Code, Codex, Cursor, …) измеряет ваш
диск в macOS, Linux или Windows, объясняет каждый крупный объект и спрашивает вас о
каждом. По умолчанию он **ничего не удаляет сам**: он пишет план, а вы запускаете его
скриптом, который заново проверяет каждый путь и спрашивает y/N по каждому пункту.

Промпт — это лишь просьба; агент может его проигнорировать. Поэтому репозиторий не
полагается только на промпт. Безопасность обеспечивают место, где происходит удаление, и
песочница или хук, которые физически блокируют агента.

## Два режима

| | **Режим плана** (по умолчанию) | **Режим выполнения** (по желанию) |
|---|---|---|
| Кто удаляет | Вы, запуская `run-plan` | Агент, один одобренный пункт на команду |
| Что агенту можно писать | Только `cleanup-plan.txt` | Одобренные удаления, каждое подтверждаете вы |
| Что это обеспечивает | Песочница ОС (рекомендуется) + guard-хук | Guard-хук + режим разрешений Manual |
| Работает с | Любым агентом | Claude Code в macOS, Linux или WSL2 |

Используйте режим плана, если нет причин поступить иначе.

## Быстрый старт — режим плана

**1. Запустите агента в пустой папке, внутри песочницы.** Песочница позволяет ему читать
диск, но операционная система не даёт ему писать за пределами этой папки.

Claude Code (macOS, Linux, WSL2):

```bash
mkdir -p ~/disk-audit && cd ~/disk-audit
```

```bash
claude --settings '{"sandbox": {"enabled": true, "allowUnsandboxedCommands": false, "failIfUnavailable": true}}'
```

Codex (macOS, Linux, WSL2 и нативный Windows):

```bash
codex --sandbox workspace-write --ask-for-approval on-request
```

В нативном Windows у Claude Code нет песочницы; там используйте Codex, Claude Code внутри
WSL2 или хотя бы guard-хук, описанный ниже.

**2. Вставьте промпт** на своём языке:

| Язык | Промпт |
|---|---|
| Русский | [`prompts/disk-cleanup.ru.md`](prompts/disk-cleanup.ru.md) |
| English | [`prompts/disk-cleanup.en.md`](prompts/disk-cleanup.en.md) |
| Türkçe | [`prompts/disk-cleanup.tr.md`](prompts/disk-cleanup.tr.md) |
| 简体中文 | [`prompts/disk-cleanup.zh-CN.md`](prompts/disk-cleanup.zh-CN.md) |
| Español | [`prompts/disk-cleanup.es.md`](prompts/disk-cleanup.es.md) |
| Português (BR) | [`prompts/disk-cleanup.pt-BR.md`](prompts/disk-cleanup.pt-BR.md) |
| 日本語 | [`prompts/disk-cleanup.ja.md`](prompts/disk-cleanup.ja.md) |

Язык промпта также задаёт язык, на котором агент вам отвечает.

**3. Отвечайте на его вопросы.** Он показывает пронумерованную таблицу, по одному объекту в
строке. Вы отвечаете номерами того, что нужно удалить, и он записывает их в
`cleanup-plan.txt`.

**4. Прочитайте план и запустите его сами** с помощью `tools/run-plan.sh` (или
`run-plan.ps1`) из клона этого репозитория. Сначала прочитайте скрипт — он короткий.

```bash
bash run-plan.sh --dry-run cleanup-plan.txt
```

```bash
bash run-plan.sh cleanup-plan.txt
```

В Windows — в обычном (не повышенном) окне PowerShell 7:

```powershell
pwsh -File run-plan.ps1 cleanup-plan.txt
```

## Что проверяет run-plan

Перед каждым пунктом и ещё раз после вашего ответа y:

- путь абсолютный и буквальный: без `~`, шаблонов и `..`;
- это не симлинк, не junction и не облачная заглушка, и ни одна родительская папка тоже;
- это не защищённое место: системные папки, домашняя папка и её папки верхнего уровня,
  ключи и keychain, почта, фотобиблиотеки, папки облачной синхронизации;
- это не корень git-репозитория или worktree;
- внутри git-репозитория путь игнорируется git, значит, это не может быть ваш исходный код;
- пункты `cmd` — одна команда без `sudo`, `rm`, конвейеров, цепочек, перенаправления,
  `git worktree remove --force` и `docker … --volumes`.

Он отказывается работать от root или с повышенными правами. Пункты, требующие повышения
прав, выводятся в конце, чтобы вы проверили их и запустили вручную. Пустой ответ или конец
ввода означают «нет».

## Режим выполнения (Claude Code)

Только если вы хотите, чтобы удалял сам агент. В режиме выполнения нельзя использовать
песочницу, потому что она блокирует запись вне рабочей папки; поэтому защиту дают
guard-хук и ваше подтверждение каждой команды.

1. Установите guard:

   ```bash
   mkdir -p ~/.ai-disk-cleanup && cp guard/disk_guard.py ~/.ai-disk-cleanup/
   ```

2. Положите [`guard/settings.example.json`](guard/settings.example.json) в папку проверки
   как `.claude/settings.json`.
3. Запустите там Claude Code в режиме разрешений **Manual** (не auto и не bypass):

   ```bash
   AI_DISK_CLEANUP_MODE=execute claude
   ```

4. Напишите в чате "execute mode".

Guard срабатывает перед каждым вызовом Bash и файловых инструментов, в любом режиме
разрешений:

- **Режим плана** (`AI_DISK_CLEANUP_MODE` не задана): проходят только команды измерения —
  `du`, `df`, `ls`, `find` без `-delete`/`-exec`, `git status`, `docker system df` и
  подобные. Всё остальное блокируется. Файловые инструменты могут писать только
  `cleanup-plan*.txt` в рабочей папке. Его стоит установить и для режима плана.
- **Режим выполнения:** дополнительно фиксированный набор команд удаления (`rm` одного
  проверенного пути, `git worktree remove` без `--force`, `npm cache clean`,
  `xcrun simctl runtime delete`, …) показывается вам как запрос разрешения. В любом режиме
  разрешений, кроме Manual, guard их отклоняет, так что без вашего клика ничего не удаляется.
- Он блокирует `sudo`, интерпретаторы (`python -c`, `awk`, `bash -c`), подстановку команд,
  перенаправление в файлы и многострочные команды. При сбое он остаётся закрытым: если нет
  Python или guard падает, хук завершается с кодом 2 и команда блокируется.

Перед началом проверьте, что он работает: попросите агента выполнить `rm -rf /tmp/probe`.
Guard должен отказать.

## Что вас защищает, а что нет

| Слой | Останавливает | Не останавливает |
|---|---|---|
| Правила промпта | Послушного агента | Агента, который их игнорирует |
| Режим плана | Любое удаление агентом | Ваше одобрение неверного пункта |
| Проверки run-plan | Симлинки, защищённые папки, неигнорируемые файлы в репозиториях, `sudo`, цепочки команд | Неверный, но допустимый путь, на который вы ответили «да» |
| Песочница ОС | Любую запись вне папки любой программой, запущенной агентом | Файловые инструменты Claude (работают вне её), MCP-серверы; нативный Windows для Claude Code |
| Guard-хук | Команды, не относящиеся к измерению, запись вне файла плана, неподтверждённые удаления | MCP-инструменты, инструмент PowerShell, инструменты кроме Claude Code, удаление хука вами |

Что остаётся на вашей ответственности:

- **Прочитать таблицу, прежде чем отвечать.** Размеры и «восстановимо» — это суждение
  агента, и оба могут быть ошибочны.
- **Удаление необратимо.** Пункты `path` минуют корзину. `quarantine` обратим, но не
  освобождает место, пока вы его не очистите.
- **Резервные копии.** Снимок перед очисткой — лучшая страховка, но сам снимок занимает
  место на диске, а именно его вам и не хватает.
- **Скрипт для Windows** (`run-plan.ps1`) ещё не запускался на машине с Windows. Сначала
  используйте `-DryRun` и сообщайте о любых странностях.

## Отказ от ответственности

**Ничего не удаляется без вашего явного одобрения — даже кэши.** Если удалено то, что вы не
называли, это ошибка: остановите процесс и [создайте issue](https://github.com/riza/ai-disk-cleanup/issues).

Проект предоставляется как есть, без гарантий. Команды выполняются на вашей машине, и
ответственность за результат лежит на вас.

## А почему не просто `du | sort`?

Потому что самая крупная добыча редко лежит там, куда смотришь первым делом, а очевидные
цифры врут. В прогоне ниже `Docker.raw`, показывавший **60 ГБ**, занимал **14 ГБ**; главным
виновником оказались **23 ГБ** git worktree от заброшенного рефакторинга; а два runtime
симулятора по **15 ГБ** лежали в `/Library`, куда сканирование домашней папки не добирается.

## Один реальный прогон

macOS, диск 494 ГБ, **заполнен на 99%, свободно 5,2 ГБ**. Этот прогон делался более ранней
версией промпта, в которой агент удалял напрямую:

| Шаг | Освобождено |
|---|---|
| Неиспользуемые git worktree в одном проекте | 4,9 ГБ |
| Папки `target/` у Rust | 5,7 ГБ |
| 83 × `node_modules` + кэши `.next` | 18 ГБ |
| `~/Library/Caches` (17 ГБ → 2,4 ГБ) | 14 ГБ |
| `~/.cache`, npm, кэш модулей Go, Homebrew | 16 ГБ |
| Runtime симуляторов iOS 17.5 и 18.0 | 36 ГБ |
| Диск ВМ Docker Desktop | 14 ГБ |
| Диск ВМ OrbStack | 11 ГБ |
| Downloads: образ прошивки на 11 ГБ + 42 установщика | 14 ГБ |
| **Итого** | **≈111 ГБ** |

**С 5,2 ГБ до 117 ГБ свободного места.** Он же показал, что исправляет эта версия: worktree
были удалены с `--force` без проверки незакоммиченной работы, а оба диска ВМ удалены при
остановленных движках, без просмотра того, какие тома в них были.

## Структура репозитория

    prompts/disk-cleanup.<язык>.md   Промпт на семи языках (английский — эталон)
    tools/run-plan.sh                Выполняет план в macOS и Linux
    tools/run-plan.ps1               Выполняет план в Windows (PowerShell 7)
    guard/disk_guard.py              PreToolUse-guard для Claude Code
    guard/settings.example.json      Настройка хука для папки проверки
    tests/                           Тесты для run-plan.sh и guard

Запуск тестов: `bash tests/test_run_plan.sh` и `python3 tests/test_guard.py`.

## Переводы

**Английская версия — эталон.** Если перевод расходится с `prompts/disk-cleanup.en.md`,
приоритет у английского. Сначала меняйте английский промпт, затем остальные. Новые переводы
приветствуются: оставляйте каждую команду ровно как есть, переводите только текст и
называйте файлы по коду BCP 47.
